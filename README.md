# PROJECT: ZERO DAY（デモ版）

**HACK THE SYSTEM. FIX THE FLAW.**

架空企業 ZERO CORP のシステムを調べて弱点を見つけ、防御ラボで設定を直して再テストする、初心者向けサイバーセキュリティ学習ゲームのプロトタイプです。すべてブラウザ内の架空データで完結し、外部への通信やコマンド実行は一切行いません。

## 環境要件

- Node.js 20 以上（22 で動作確認）
- npm 10 以上
- モダンブラウザ（Chrome / Edge / Safari / Firefox の最新版、スマホ対応）

## 起動手順

```bash
npm install
npm run dev        # 開発サーバー（http://localhost:5173）
npm test           # 判定ロジックの自動テスト（22件）
npm run build      # 型チェック + 本番ビルド（dist/）
npm run preview    # ビルド結果の確認
```

`dist/index.html` は相対パスで出力されるため、GitHub Pages などにそのまま置けます。

## スマホアプリとして使う（PWA）

このアプリは PWA（ホーム画面に追加できるWebアプリ）です。追加すると、ブラウザの枠なしの全画面で起動し、一度開けば電波がない場所でも遊べます。

### GitHub Pages で公開する

1. GitHub に新しいリポジトリ（例：`zero-day`）を作り、このフォルダの中身を `main` ブランチに push
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選ぶ
3. push のたびに `.github/workflows/deploy.yml` がテスト → ビルド → 公開を実行
4. 公開URL：`https://<ユーザー名>.github.io/<リポジトリ名>/`

### スマホに入れる

- **iPhone（Safari）**：公開URLを開く → 共有ボタン → 「ホーム画面に追加」
- **Android（Chrome）**：公開URLを開く → トップ画面の「追加する」ボタン、またはメニュー →「アプリをインストール」

### 更新を配信するとき

画面やミッションを変えて公開したら、`public/sw.js` の `CACHE`（例：`zero-day-v1` → `zero-day-v2`）を上げてください。古い保存データが確実に入れ替わります。進行状況（XPなど）は消えません。

## 遊び方

初回起動時に5ページの「遊び方」ガイドが表示されます（ヘッダーの「遊び方」ボタンからいつでも再表示できます）。

1. ダッシュボードの「ミッションを開始」で MISSION 01 から始める
2. ターミナルにコマンドを入力（Enter で実行、↑↓ で入力履歴）。まずは `help`。書き方はターミナル下の「コマンドの書き方」に、押すと入力欄に入る例つきでまとめています
3. 調査で「証拠」を集めると、左の達成条件にチェックが付く
4. 証拠がそろったら原因を `submit <リソース名>` で報告。3回まちがえると失敗
5. クリア後は結果画面で解説を読み、防御ラボで設定を直して「再テストを実行」

ヒントは3段階（注目する場所 → 調査の考え方 → 解答と理由）。1段階ごとに獲得XPが20%減ります。

### ミッション

| # | 名前 | 内容 | XP / 防御XP |
|---|------|------|-------------|
| 01 | RECON | 公開サーバーの想定外ポートと、デバッグモードのまま公開された管理画面を見つける | 100 / 50 |
| 02 | BROKEN AUTH | テストケースで空パスワードのログイン成功を再現し、原因の設定項目を特定する | 150 / 75 |
| 03 | DATA LEAK | 請求書APIで他人のデータが見える不具合（IDOR）を再現し、原因の処理を特定する | 200 / 100 |

各防御ラボには「攻撃は止まるが正規の利用者も使えなくなる」やりすぎ設定も用意しています。攻撃テストと正規利用テストの両方に合格すると防御成功です。

## ゲームシステム

- ランク：ROOKIE → CADET(150) → ANALYST(350) → OPERATOR(550) → ZERO DAY HUNTER(650)
- XPは初回クリア・初回防御成功時のみ付与（再クリアで増えない）
- 進行状況・途中のターミナル・ヒント履歴は localStorage に保存（再読み込みしても保持）
- ダッシュボード下部の「デモデータを初期化」ですべて初期状態に戻せる

## 構成

```
src/
  game/                 UIから独立したロジック
    types.ts            型定義
    engine.ts           コマンド解析・実行（許可リスト方式）
    defense.ts          防御テストの判定
    progress.ts         XP・ランク・保存と復元
    missions/           ミッションデータ（recon / brokenAuth / dataLeak）
    *.test.ts           自動テスト（node:test）
  hooks/useGame.ts      状態管理と保存
  components/           画面（Dashboard / Workspace / ResultScreen / DefenseLab ほか）
  styles.css            デザイントークンと全スタイル
  pwa.ts                Service Worker 登録・インストール判定・振動
public/
  manifest.webmanifest  アプリ名・アイコン・全画面表示の設定
  sw.js                 オフライン用のキャッシュ
  icons/                アプリアイコン（192/512/マスカブル/Apple用）
.github/workflows/      GitHub Pages への自動公開
```

## 安全設計

- コマンドはミッションごとの許可リストのみ受け付け、対象もミッションに定義された固定リソース名だけ
- IPアドレスやURLらしき入力、全角文字、シェル記号（`; & | $` など）は拒否
- 実際のネットワーク通信・OSコマンド・コード評価は一切なし
- アカウント・パスワード・請求書などはすべて架空の演習データ
- 画面上に「SIMULATION」「仮想演習環境」を常に表示

## 既知の制約（デモ版）

- ミッションは3つ、シナリオは固定（ランダム要素なし）
- 進行状況はブラウザごとの保存で、端末間の同期やログイン機能はなし
- 演習対象の疑似画面（ログイン画面や請求書ポータルの見た目）は未実装で、操作はターミナル中心
- UI の自動テスト（E2E）は未整備。テストは判定ロジックが対象
- フォントは Google Fonts から読み込み（初回オンライン時に保存し、以降はオフラインでも表示）
- 振動フィードバックは Android のみ（iPhone の Safari は非対応）
- App Store / Google Play への登録は対象外（ストア配信には Capacitor などでの包み直しが必要）
